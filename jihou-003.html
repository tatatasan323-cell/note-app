PHPに深刻な欠陥。修正版は出たが、自動では入らない

特報

PHPに、ログイン不要で、外から届くリクエストだけでサーバーに命令を実行されうる欠陥が見つかった。 通称「php2shell」。2件（CVE-2026-109618／109619）で、深刻度は10点満点中9.2とされる。

修正版は10月21日前後に出たが、自動では入らない。 8.1以前は、公式の修正版バイナリが出ていない。 公開の前の10月17日から攻撃の試みがあったと、セキュリティ各社が報告している。 一方、公的機関の悪用リスト（CISA KEV）には、10月23日の確認時点でまだ載っていない。

同じ10月21日に、Node.jsも10件の脆弱性を修正した。うち深刻度が高いものが4件。 AIに作らせた社内ツールは、Node.jsで動くことが多い。 自社が当たるかどうかは、誰が・どこで・何版で動かしているかを知るところから決まる。 PHPやNode.jsが何かは、下の「ことば」の欄で説明している。

CONCLUSION

先に、結論だけ

今日やることは、三つである

  1. 棚卸しをする

    自社で動いているPHPとNode.jsを、「誰が・どこで・何版で」の3点で書き出す。担当者がいなければ、運営業者への問い合わせがそのまま棚卸しになる。

  2. 業者に三つ聞く

    自社サイト・予約や問い合わせの仕組み・古い業務システムは、運営業者に聞くのが早い。下の文面をそのまま送れる。

  3. AIで作った道具は、攻撃を流して確かめる

    ファイル名や表のセルに、画像を装った命令を入れて取り込ませる。命令が実行されなければ、まず合格である。

業者に送る文面（そのまま使える）

お世話になっております。
10月21日前後に公表されたPHPの脆弱性（CVE-2026-109618／CVE-2026-109619）について、次の3点を教えてください。

1. 当社のサイト（システム）で動いているPHPの版は何ですか。修正を取り込んだ版ですか。
2. PHP 8.1以前を使っていませんか。
3. 8月1日以降の、不審なアクセスの記録を確認しましたか。

更新は、止めてよい日を選んでやるものである。 ただし今回は、公開の前から攻撃の試みがあったと報告されている。 「次の定期メンテナンスで」ではなく、今週中に、まず問い合わせだけでもしておきたい。

WORDS

PHP と Node.js とは

専門家でなくても、役割だけ押さえればよい

Webサイトの画面が届くまでには、裏でコンピューターが働いている。 この裏方のコンピューターを、サーバーと呼ぶ。 お店にたとえるなら、客席がお客さんの画面で、厨房がサーバーである。 注文を受けて、料理を仕上げて、出す。 その調理の手順を書くための言葉が、PHPとNode.jsである。

PHP（ピー・エイチ・ピー）

Webサイトの裏側で動くプログラムを書くための、プログラミング言語。 1990年代から使われている。 ブログやホームページを作る仕組みのWordPressも、PHPで作られている。

自社サイト、予約や問い合わせのフォーム、何年も触っていない業務システムの中で、動いていることが多い。 自社が使っているかどうかは、運営業者に聞けばすぐ分かる。 自社サイトがWordPressなら、答えは「使っている」である。

Node.js（ノード・ジェイエス）

ブラウザの中で動く言葉のJavaScriptを、サーバーでも動かせるようにした仕組み。 Node.jsの道具は、npmという部品の置き場から、必要な部品を取り寄せて組み立てる。

AIに「Webの道具を作って」と頼むと、Node.jsで動く構成になることが少なくない。 一方、HTMLファイルを開くだけで動く道具は、Node.jsを使っていない。

対象になる動かし方

Apache の mod_php がもっとも危険とされ、PHP-FPM・php-cgi・FrankenPHP・LiteSpeed も対象である。 mod_php では、アプリが動き出す前の、認証のない要求だけで引き金が引かれうる。 アプリの中のWAF（攻撃を遮る仕組み）では防げない可能性がある、とPHPプロジェクトは説明している。

ことばの補足
Apache と mod_php
Apache（アパッチ）はWebサーバー用のソフトの名前。mod_phpは、その中でPHPを動かす方式で、今回もっとも危険とされた。

番号だけでは、修正済みかどうか分からない

OSによっては、PHPの番号を上げないまま、修正だけを取り込む配り方をする。 AlmaLinux は、php -v（PHPの版を表示する命令）の番号では修正済みか分からないとして、パッケージの版の確認を案内している（例：rpm -q php-common）。 他のOSでも同じかどうかは、確認していない。

ことばの補足
OS（オーエス）
コンピューターの土台になる基本ソフト。WindowsやMacの仲間。
AlmaLinux（アルマリナックス）
サーバー向けに広く使われる、OSのひとつ。
パッケージ
OSの部品を配る時の、まとまりの単位。部品ごとに、版の番号がつく。

応急処置は、更新の代わりにならない

PHPプロジェクトは、更新できない場合の応急処置も示している。 メモリ上限の扱い、アップロードの進捗機能の停止、アップロードを受けないなら受け付けの禁止、などである。 ただし、攻撃の入口を一部ふさぐだけで、更新の代わりにはならない。 設定を変えたら、PHPを再起動し、実際のWebリクエストで有効になったかを確かめる。

NODE.JS

ことばの補足｜Brotliの欠陥とは

Brotli（ブロトリ）は、データを小さくして送るための、圧縮形式のひとつ。荷物にたとえるなら、箱に詰めて小さくした状態である。受け取った側は、使う前に、その箱をほどく。これを「展開」と呼ぶ。Webでは、通信を速くするために、よく使われている。

今回の欠陥は、この「箱をほどく」処理の中にあった。ほどく途中で、決められた置き場所をはみ出して、データを書き込んでしまう。この置き場所を「メモリ」と呼ぶ。プログラムが動いている間、データを一時的に置いておく、作業台のようなものである。専門用語では「範囲外書き込み」と呼ぶ。はみ出した先には、プログラムが動くための大事な情報があることがある。そこを狙って作った細工入りのデータを渡されると、命令を実行されるおそれがある。Node.js公式は、この欠陥の深刻度を「高」としている。

確かめていないこと｜どんな使い方で当たるのか

どんな使い方で当たるのかは、公式のページに書かれていない。

報道には、「外へ通信する機能（fetch）や、特定のWebの枠組みで特に関係する」との指摘もあるが、確認できていない。fetchは、プログラムが、外のサイトへデータを取りに行く機能の名前である。

仕組みから考えると、外から受け取った圧縮データをNode.jsで展開する場面（外部のサイトからデータを取ってくる処理、ファイルを受け付ける処理など）が危ういと思われるが、これは推測である。確かなのは、修正版に更新すれば、この欠陥がふさがる、ということである。外から圧縮データを受け取るアプリは、念のため優先して更新しておきたい。

ことばの補足
TLS
アドレスが https:// で始まる通信を暗号化する仕組み。「いま話している相手が、本物か」の確認も、受け持っている。この確認をすり抜けられると、偽の相手を、本物と信じてしまうおそれがある。
名前の引き当て（dns.resolve）
サイトの名前から、その場所（番号）を調べる処理。電話帳で、名前から電話番号を調べるようなもの。名前が途中で切られると、調べる相手が、意図と変わってしまう可能性がある。

Node.js 公式は、サポートが終わった版は、セキュリティリリース（弱点を直した版の公開）のたびに必ず影響を受けると書いている。 公式の一覧では20系と25系が終了と表示されており、今回の修正版も出ていない。 AIに作らせた社内ツールを動かす版が20系・25系なら、移行先を決める必要がある。

npmの部品汚染とは

今回の修正とは別の話だが、Node.jsの道具を使うなら、知っておきたい話である。

Node.jsの道具は、たくさんの部品を組み合わせて作られる。 npmという置き場から、必要な部品を取り寄せて、組み立てる。 料理にたとえると、市場で仕入れる食材である。 その食材に、毒を混ぜる。これが部品汚染である。

部品が乗っ取られると、本物の部品に、悪意のあるプログラムが混ざった「新しい版」が公開される。 何も知らずに、いつもどおり部品を更新すると、毒入りの版が、そのまま自分の道具に入ってしまう。 部品の中には、「入れる時に自動で走る処理」を仕込めるものがある。 新しいnpmは、この自動処理を既定で止める。古い環境では、動いてしまう。

第002号では、8月4日に起きた事例を扱った。 乗っ取られた部品が、盗んだ権限で次の部品を汚染しながら、約30分で数百の部品に広がった。 盗まれたのは、GitHubやnpmの鍵、クラウドの鍵などである。

AIに道具を作らせると、気づかないうちに、たくさんの部品が入ることがある。 自分で書いたコードでなくても、自分の道具の一部になる。 入れている部品の一覧を、人が把握しておく。対策の入口は、そこである。

この紙面は10月22日〜23日時点の情報で、更新は続いている。

WORKSHOP

工房を、全部開けて見た

PHPもNodeも、サーバーでは動かしていない。だが別の穴が、4つあった

工房の成果物に、サーバーとして動かすPHP・Node.jsはない。 検査のために使っている道具が内蔵するNodeは修正前の版（v24.14.1）だったが、手元の検査にだけ使っており、優先度は低いと見ていた。今回のタイミングで更新し、いまは修正版の v24.22.1 である。

そのうえで全成果物を点検したところ、取り込んだファイルの文字が、そのまま画面になってしまう穴（XSS）が4つ見つかった。 いずれも、AIに書かせた道具である。

XSSとは ── 取り込んだ文字が、命令になる穴

XSS（クロスサイト・スクリプティング）は、Webの画面にまつわる、古くからある弱点である。

画面には、いろいろな文字が表示される。ファイルの名前、表のセルの中身、フォームに入れた文章。 その文字の中に「命令」が混ざっていて、画面を作るプログラムがそれを「ただの文字」と見分けられないと、ブラウザは本物の命令として実行してしまう。 これがXSSである。

たとえるなら、朗読係である。 「この紙を読み上げてください」と頼んだら、紙に書いてあった「金庫を開けなさい」まで実行してしまった。 読み上げるだけにしておけば、何も起きない。 この「読み上げるだけにする」処理を、無害化（エスケープ）と呼ぶ。

命令が実行されると、その画面に出ているデータを読み取られる、画面を書き換えられて偽の入力欄を出される、といったことが起こりうる。 ログインして使うサイトでは、本人になりすました操作をされることもある。 ファイルを取り込む道具や、入力した文字を画面に出す道具は、特に起こりやすい場所である。 人が書いた道具でも、AIが書いた道具でも、起こりうる。

検査は、画像を装った命令を、ファイル名・列名・セル・シート名に仕込んで取り込ませ、実際に実行されるかを見るやり方である。 「実行」は、命令が走った回数である。「不正なタグ」は、命令を含んだ、細工入りの部品が、画面に紛れ込んだ数である。

守りは、三つ重ねた

無害化（エスケープ）

本筋の守り。画面に出す文字を、すべて「ただの文字」に変えてから出す。

朗読係に「紙の内容は読み上げるだけ。実行はしない」と徹底させるのに近い。

四つの道具すべてに入れた

CSP（シー・エス・ピー）

保険。「この画面は、ここまでしか許可しない」という決まりを、ブラウザに守らせる設定。

部品を読み込める場所や、外への通信を、決めた範囲に絞る。会社の入館ルールに近い。

万一、命令が混ざって実行されても、外へデータを持ち出す道を絞れる。

#06記事の道具・tenki-zero 体験版に入れた

SRI（エス・アール・アイ）

外から取り寄せる部品の「封印シール」。

本物の部品の中身から計算した値（指紋のようなもの）を、あらかじめ登録しておく。届いた部品の値が違えば、ブラウザは使わない。

配信元が乗っ取られて、中身がすり替えられても、動かない。

外から読み込む部品があるのは #06記事の道具だけ。読み込み元も2か所に絞った

どの道具に、どの守りを入れたか
道具無害化CSPSRI
#09記事 自動DB変換ツール○――
#06記事 食品ロス可視化ツール○○○
#12記事 売上集計ツール○――
tenki-zero 体験版○○―

「―」は入れていない。外から読み込む部品がない道具（#09・tenki-zero）には、SRI は要らない。

#06記事・#09記事・#12記事で配布した道具の旧版にも、同じ穴があった。 各記事の添付ファイルは、修正版に入れ替えてある。 お手元の旧版をお使いの方は、入れ替えをお願いしたい。

同じ点検で、手元で動かす城のサーバにも、名前の偽装・別サイトからの書き込み・防御ヘッダの3つの口を塞ぐ手当てをした。 ハロウィンのカードの公開版にも、CSPを入れている。

今後は、このような穴を、最初の成果物の時点でなくしていく。 AIはこちらの意図した成果物を作るが、その条件に入れる安全項目やセキュリティ項目は、こちらの地力を上げなければ盛り込めない。 今回は、その典型的な例と言える。 非エンジニアだからこそ欠かせない手として、今回の課題は大変ためになった。

一言にすると

動くことと、穴がないことは、別である。
